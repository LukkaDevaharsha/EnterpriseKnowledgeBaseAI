# Enterprise Knowledge Base frontend

React 19 and Vite UI for the existing Flask API. The app includes employee
registration with email verification, login by email or Employee ID, session
restoration, document management, semantic search, RAG questions, shared admin
knowledge management, and a PDF study workspace.

## Run locally

Start Flask in a PowerShell terminal:

```powershell
cd D:\MY_PROJECTS\EnterpriseKnowledgeBaseAI\backend
..\.venv\Scripts\python.exe run.py
```

The development API listens on `http://127.0.0.1:8000`; debug mode remains
controlled by the backend's development configuration. In a second terminal:

```powershell
cd D:\MY_PROJECTS\EnterpriseKnowledgeBaseAI\frontend
npm run dev
```

Open the local address printed by Vite. During development, `/api` requests
are proxied to `http://127.0.0.1:8000` by `vite.config.js`.

For a separately hosted API, set `VITE_API_BASE_URL` to its origin at frontend
build time. If left unset, requests use the same origin under `/api`, which is
appropriate when a reverse proxy serves both the frontend and API together.
Do not put credentials or secrets in Vite environment variables; values with
the `VITE_` prefix are included in browser assets.

## Features and API behavior

- Public routes: `/login` and `/register`. Registration sends `name`, `email`,
  `department`, and `password`; Employee IDs are generated by the backend and
  privileged roles cannot be selected.
- Protected routes: `/`, `/documents`, `/search`, `/ask`, `/study`, and `/admin`
  (the last requires an admin role in both UI routing and backend APIs).
- Registration collects the verification code through the backend's email OTP
  endpoints. A pending email is remembered for the current browser session;
  codes are not stored by the frontend.
- JWTs are attached to protected API calls and restored from browser storage
  after refresh. An expired token signs the user out. Logout is available in
  the authenticated header.
- Document upload, listing, download, and deletion use the existing API.
  Uploads accept PDF/TXT up to 10 MB.
- Search and question-answering render the response fields from the backend,
  including citations and the distinction between general and document-grounded
  answers. No conversation-history API exists, so questions are not persisted.
- Admins can review system statistics, manage employee role/status, inspect
  indexing status, and upload/delete shared documents.
- Study PDFs are fetched through authenticated API requests. Search highlights
  are shown in the extracted text panel and page navigation targets the native
  browser PDF viewer. Highlight overlays directly on the PDF canvas require a
  maintained PDF rendering dependency; that dependency is not currently
  available in this workspace.
